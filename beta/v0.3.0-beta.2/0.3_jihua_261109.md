## 1. 目标与硬边界

### 1.1 版本定位

AI Agent 接入与执行治理：让不同来源的 AI Agent 接入统一治理内核，在执行操作前接受规则审查，并产生可追溯的治理结果。

### 1.2 硬边界（原文明确）

- **不追求全面监管**：全过程实时监控、强制拦截属 0.4／0.4 以后，不在 0.3。
- **不得宣称拦截真实操作**：0.3 只提供标准化执行授权结果与适配接口；实际执行是否受控，取决于 Agent 是否通过受治理的执行适配器调用工具。
- **治理决策 ≠ 执行成功**：`ALLOW` 只代表规则允许，不代表操作已执行。
- **注册 ≠ 可信任 ≠ 全权**：Agent 注册与能力声明都不自动赋予权限。
- 工程侧：不改已发布三端行为、不改判据与 `rule_id` 口径、不重写 0.2 的账本链与四外键。

## 8. 风险与停手条件

| 风险 | 表现 | 停手条件 |
|---|---|---|
| 契约冲突 | 0.3「统一接口／适配器／控制台」若做成服务/SDK/IPC，触碰 `HOST_CONTRACT.md:162`（内核内无 http/socket/grpc/daemon/server/api） | 立刻停，列冲突报裁；不自行取舍 |
| 契约扩员 | Agent 身份/能力若要求成为 12 成员契约必需项（`HOST_CONTRACT.md:104`） | 同上 |
| 决策值域冲突 | 五值若直接替换 0.2 的 `result` 四值（`supervisor.py:157/460/492/518/764`） | 只能新增 `decision` 字段并存，不得改判据 |
| 冒认「已接规则体系」 | beta1 自带规则包却被写成「调用现有体系」 | 立即按事实更正，重发说明 |
| 把决策当执行 | 宣称已拦截真实操作 | 立即收回；原文明确禁止 |
| 另造第二套账 | 新建与 `ActionLedger` 并列的账本 | 立即停止，改为复用 |
